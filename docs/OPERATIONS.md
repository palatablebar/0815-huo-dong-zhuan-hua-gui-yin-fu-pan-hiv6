# 批次操作

1. 用带异常样例做阶段预览，查看列数、必填值和冲突记录。
2. 执行批次后，在“归因账”页核对每笔转化的净额、渠道功劳与差额；“直达记录”“无触点案例”页把两类不占渠道功劳的净额单独披露，同时仍按未对平列出记录键。
3. “阻断项”页列出仍需处理的记录键：冲突、窗口缺口、未对平（含直达与无触点）和参考值差异。全部清空后 `balance.releasable` 才为真。
4. 修复来源文件，重新上传并执行。同一来源重跑会命中同一账本，不会重复累计功劳；来源更新后只重算受影响的转化，其余结转并标注上游批次。
5. 对账无差异且无阻断项时可签发；对仍有差异的版本可填写暂缓意见。历史批次与旧版证据保留在版本链中。
6. 导出复核证据并保存于交接记录；证据包内含 `lineage`、`versions`、`reconciliation` 与直达/无触点专列，可复算每一分。

单文件 256 KiB，最多 2000 条逻辑记录。容器重启后保留批次。恢复时使用原 Docker Compose 数据卷。
