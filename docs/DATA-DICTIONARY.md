# 字段与业务定义

输入编码 UTF-8，允许 BOM。首行必须匹配样例列顺序。记录键和业务组保留原始字符串。`kind` 允许 touch, conversion, expected。说明列 `note` 可以跨行，限制 200 字。

业务字段按 `minute`、`channel`、`consent`、`value_cents`、`lookback` 排列。数字接受非负整数、全角数字和完整千分位。空串、短横线、N/A、NULL 与未知为缺值。无关字段用 0 占位。

## 归因口径

- 参与触点：`consent = 1`、`channel != 0`（非直达），且 `minute` 落在回溯窗口 `[conversion.minute - lookback, conversion.minute)` 内。窗口包含回溯起点，排除转化时刻。
- 同一笔转化净额（`value_cents`）在全部参与触点之间等分；整数分按记录键升序补齐，保证重跑结果稳定、各触点入账之和恰好等于净额。每个触点带名义份额 `share` 与实际入账 `credit_cents`。
- 渠道功劳按渠道号汇总；任何一次转化的渠道功劳合计必须恰好等于净额，且任何渠道都不得高于净额 —— 逐条对平。
- 直达触点（`channel = 0`）不占渠道功劳，直达记录单独列出（`direct`、`direct_only`）。
- 回溯窗口内没有合规触点的转化记为无触点案例（`no_touch`），单独列出。
- 直达与无触点的渠道功劳为 0，与净额无法逐条相等，因此同样记为未对平并挡住签发；其净额以 `direct_cents` / `no_touch_cents` 留在账内，不冒充渠道业绩，也不会消失。
- 窗口缺口：回溯起点早于来源可观测起点（默认 0 分钟）时，窗口内可能少了看不见的更早触点，记录键列入 `window_gaps` 并挡住签发。

`incoming.csv` 包含四个业务组，第二组提供不同边界，第三组触发无触点，第四组需要核对。另含重复表头、冲突记录、重复回放与错误列数。`ready.csv` 含可以签发的两个组。
